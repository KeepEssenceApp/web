# 词表

全套文档、界面和接口只用这些词，一词一义。产品名待定：文档中写「本产品」，品牌素材暂用 KeepEssence（见 brand/）。界面和对外文字用左边的中文词，接口和代码用中间的英文。动词用直白的英文（create、claim、submit、expire）。不用比喻。

处理流程：**条目 → 初筛 → 解读 → 每日摘要**；深挖队列中的条目 → **精读 → 深挖 → 笔记**。

| 中文 | 英文 | 是什么 | 寿命 | 谁产生 |
|---|---|---|---|---|
| 条目 | item | 用户攒存的原始内容（网址、文字、图片、文件）。过期、收藏规则同原文 | 缺省 30 天，最长一年；收藏的不过期 | 用户 |
| 初筛 | triage | 分派助手快速决定一条交给哪个助手处理、保留多久，结果写成标签。不发通知 | 跟条目 | 分派助手 |
| 解读 | analysis | 助手对单个条目的分析，固定四项：内容概述、关键事实、要点、判定 | 跟条目 | 做解读的助手 |
| 判定 | verdict | 解读的第四项，三选一：值得深挖、知道就行、可以略过 | 跟解读 | 做解读的助手 |
| 每日摘要 | daily digest | 一天内所有解读汇总成的一份摘要，不过期 | 不过期 | 做汇总的助手 |
| 精读 | deep read | 定时型助手对深挖队列中的条目做完整阅读和补充查证，输出精读报告。不算笔记 | 跟队列里的那一条 | 定时型助手 |
| 深挖队列 | deep-read queue | 用户计划深入讨论的条目清单。每条只记核心看得到的事：加入的时间、精读的状态、用户去过没有、助手取过没有 | 有笔记交回、用户移出或 7 天没动静为止 | 用户 |
| 深挖 | deep-dive session | 用户与对话型助手的讨论过程。过程不存在核心里 | — | 用户与助手 |
| 深挖登记 | deep-dive request | 用户去深挖时，核心登记的一条：开场话或链接。界面上不用这个词 | 同深挖队列 | 用户 |
| 笔记 | note | 深挖的最终产物，可带附件 | 不过期 | 助手，经用户确认 |
| 标签 | tag | 条目上的处理指令，写成 `种类:值`，对用户隐藏 | 跟条目 | 分派助手、核心、用户 |
| 规则 | rules | 用户写给分派助手的话，加几项助手设置 | 用户改前一直有效 | 用户 |
| 关联提示 | related hint | 解读时发现的「和以前的内容有关联」的提示 | 跟解读 | 做解读的助手 |
| 偏好说明 | preference note | 助手从「不感兴趣」和深挖记录里提炼的一段话，分派助手初筛时参考。v1.0 不做 | — | 助手 |
| 助手 | assistant | 任何接入的 agent。分两类：定时型（按时间表运行）、对话型（只在用户对话时运行） | — | 用户接入 |
| 分派助手 | dispatch assistant（Scout） | 我们提供，免费，负责初筛 | — | 我们 |
| 自带助手 | own assistant | 用户接入的助手，免费 | — | 用户 |
| 工作助手 | worker assistant | 我们提供的助手，做解读和汇总，对外叫「内置助手」。内测期间提供、不收费；正式推出后收费 | — | 我们 |
| 定时型助手 | scheduled assistant | 能按时间表自己运行的助手。可以解读、汇总、深挖；精读只由它做 | — | 接入时定 |
| 对话型助手 | chat assistant | 只在用户和它聊天时干活的助手。只能深挖，不能精读 | — | 接入时定 |
| 助手设置 | assistant settings | 一个用户的全部助手加他的规则 | — | 用户 |
| 核心 | core | 服务器。唯一说了算的地方 | — | — |
| 契约 | contract | 核心对外的接口定义 | — | — |
| 攒存 | accumulate-save | 内部专业词，指采集这一动作：内容在一段时间里攒进来，不是一次性的。内部文档统一用它；接口动词统一为 `save`。界面和对外文字不用，界面统一叫「存入」 | — | 用户 |
| 存入 | save | 攒存的对外叫法，界面和对外文字统一用它，让用户觉得内容已经落袋为安。用户把内容存入，成为一个条目。客户端权限名「只存入」也用这个词 | — | 用户 |
| 删除 | delete | 对用户的口径：条目到期，或用户自己删除，用户都看不见，界面和对外文字统一叫「删除」。内部实际流程是过期、归档、系统清理（见「过期」「归档」）；保留规则由配置决定，对外说明见 数据保留说明（尚未发布） | 同条目 | 核心 |
| 过期 | expiry | 内部用语：条目到期，核心把它设为归档（[techspec](techspec.md) §6）。对用户不用这个词，一律叫「删除」 | 同条目 | 核心 |
| 归档 | archive | 内部用语：过期后条目的保存方式，用户看不见，对用户口径为「删除」。见 [techspec](techspec.md) §6 | 见 open #46 | 核心 |
| 收藏 | pin | 用户把条目的过期延到不过期。条目还是条目，解读跟着留下；不需要精读或深挖。可以改回 | 用户改回为止 | 用户 |
| 读了 | read | 对一份每日摘要的已读标记 | — | 用户 |
| 不感兴趣 | not interested | 对一条解读或每日摘要里一条的可选标记。负向信号 | 跟解读 | 用户 |
| 看过了 | seen | 同上，表示已经知道。不是信号 | 跟解读 | 用户 |
| 状态栏 | status bar | 常驻显示助手状态的一栏：几只助手在工作、各自上次来的时间、今天存入了几条、几条在等 | — | 核心 |
| 通知 | push notification | 核心发给用户设备的一句话：核心内置助手完成了某条的解读或精读。初筛不发；用户自带助手的也不发，见 [techspec](techspec.md#9-处理完成通知) | — | 核心 |
| 提醒 | ping | 核心发给助手的「有活了」，不带内容。和给用户的通知是两回事 | — | 核心 |
| 设备 | device | 一个接入的客户端或助手。有名称，可单独撤销 | 撤销为止 | 授权流程 |
| 权限：只存入 | submit | 客户端权限的最低一档：只能存入，看不到内容 | — | 授权时定 |
| 权限：读 | read | 中间一档：能读，能对解读和每日摘要做动作 | — | 授权时定 |
| 权限：管理 | manage | 最高一档：还能管理助手设置、规则和设备 | — | 授权时定 |
| 月历 | monthly calendar | 一个月的图，一天一个圆点（与 `brand/visual.md`（品牌资料暂未公开） 一致），表示当天存入、每日摘要、笔记的情况 | 不过期 | 核心 |
| 今天 | today | 读的界面的第一个入口：已存入、还没进每日摘要的东西 | — | — |
| 授权 | authorize | 接入的唯一方式：用户在 本产品 的页面上点允许。客户端核对短码，助手走允许页 | — | 用户 |
| 接入地址 | — | 核心的 MCP 地址。所有用户相同，不是凭据，可以复制 | — | — |
| 开场话 | opening line | 从产品发起深挖时带给对话型助手的一句话，不含内容 | — | 核心 |
| 认领 | claim | 一只助手领走一份活，别的助手不再做 | 缺省 30 分钟 | 助手 |
| 署名 | — | 每个产物记下由哪只助手做 | 跟产物 | 核心 |

## 不用的词

书签、决定（作名词）、知识库、存档、搜索、分类、主题、喜欢、不喜欢、首页、设置（作入口名）、钥匙、token、API key。

比喻一律不用，包括：花、蜜滴、判断（作正式名，用「判定」）、花蜜、晚课、蜂蜜、蜂王浆、蜂、蜂群、蜂巢、采、吸蜜、归巢、酿、凋谢、封盖、养蜂人、摇摆舞、口味、骨架、工蜂。

界面和对外文字统一用上表的中文词。「攒存」是内部专业词，界面和对外文字不出现，界面叫「存入」；「采」只作为比喻列里的禁用词保留，不作为任何动作名。「暂存」已弃用，不用。以后再有新的比喻，替换成上表的词或直白的说法。
